# 개념 시각화 감사 기준 (2026-10-15)

기준 예시: `src/pages/articles/ai/prefill-decode-phase-dynamics/viz/LayerPassViz.tsx`, `LayerLoopProcessViz.tsx`.

글마다 **핵심 메커니즘**(독자가 "왜/어떻게"를 헷갈리는 지점)을 1~3개 고르고, 각 메커니즘이 아래를 만족하는 Viz로 보이는지 판정한다.

| 등급 | 뜻 |
|---|---|
| A 메커니즘 Viz | 실제 구조(칸·행렬·경로·큐·블록)를 그리고, 장면이 넘어갈 때 상태가 바뀌며(움직임 또는 단계), 화면의 칸/숫자를 독자가 직접 셀 수 있다. 한 Viz = 한 메커니즘. |
| B 부분 | 구조는 그렸지만 상태 변화가 없거나(정지 그림), 숫자만 바뀌고 구조가 안 움직이거나, 핵심이 아닌 주변 개념을 그림 |
| C 장부·카드 | 숫자 장부, 막대 하나, 카드/칩 나열, 텍스트 박스 흐름도. 개념의 흐름을 그림만으로 말할 수 없음 |
| — 없음 | 그 메커니즘을 다루는 Viz 자체가 없음 |

판정은 Viz 코드(.tsx)와 본문을 읽어 내린다. 숫자 장부(CalculationWalkthrough), AlgorithmBlock, 표는 Viz로 세지 않는다.

각 글 산출 항목:
1. 핵심 메커니즘 1~3개(한 줄씩, 독자의 헷갈리는 질문 형태)
2. 기존 Viz 목록과 등급(파일명 · 등급 · 한 줄 이유)
3. 메커니즘별 커버 여부
4. 부족하면 새 Viz 설계안: 그릴 구조(행/열/요소), 장면 목록(3~6개, 장면마다 무엇이 바뀌는지), 화면에서 셀 수 있는 숫자(글의 running example 숫자 재사용), 넣을 절 id
5. 우선순위: P1(핵심인데 C/없음) · P2(핵심인데 B) · P3(괜찮음)
