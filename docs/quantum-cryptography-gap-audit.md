# 양자 계산·양자내성암호·양자키분배 누락 검수

확인 기준일: 2026-10-04. 네 정본 신설과 계정 글 심화를 마쳤고 전체 배포 검수는 공통 보고서에서 추적합니다. 기존 crypto 44편과 blockchain/pq-account의 실제 import 경로, 개념 그래프를 대조했다.

|---|---|---|

## 출처와 재현 범위

- FIPS 203·204·205 최종본과 각각의 최신 errata 안내, NIST SP 800-227 최종본(2025-09).
- PQClean 0586a824fc0d49df0b6b6e9179d8d15d06d0974f의 ML-KEM-768·ML-DSA-44 C 소스 및 라이선스 보존.
- account-abstraction 1c6b669d0eea734e09a87e095ba15e076151718a의 원문 보존. 기존 설명용 축약 코드를 upstream 원문으로 사용하지 않는다.
- Shor·Grover 원 논문, IBM 강의, 2026 ECDLP 자원 추정 논문. 자원 추정은 현재 장치에서의 해독 성공을 뜻하지 않는다.
- ITU-T X.1711(03/2026)과 QKD 원 논문·실험 및 인증/장치 제약을 대조한다.
- 작은 숫자 사례는 원리를 확인하는 교육용 계산이다. 표준의 안전한 파라미터나 제품 인증, 실장치 성능 시험이 아니다.

## 검산과 설명 검수

- Grover 네 진폭의 1회·2회 변환, Shor의 15·밑2·256개 지수와 측정 확률, mod17 키 합의와 서명 상쇄를 작성자와 별도 검토자가 각각 계산했다.
- Shor의 중간 상태를 측정한 뒤에는 상태를 새로 준비해 재실행한다는 조건을 명시했다. 순수 상태의 얽힘 설명을 혼합 상태에 일반화하지 않았다.
- FIPS203의 외부 입력 검사와 PQClean 내부 복원 함수의 책임을 구분했고, 서명 소스의 실제 행 번호를 재대조했다.
- root 작성 3편은 1440/390 화면 6개, ML-KEM·ML-DSA 코드 패널 6회 열기·닫기 검사에서 오류가 없었다. QKD와 계정의 검수는 Web3 검수 기록에 포함한다.
- NIST 정정표의 존재·날짜는 확인했지만 접근 제한으로 정정표 파일 내용은 직접 읽지 못했다. 이를 구현이 정정 사항까지 모두 반영했다는 주장으로 바꾸지 않았다.
