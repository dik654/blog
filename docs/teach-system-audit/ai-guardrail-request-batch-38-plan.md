# AI 가드레일 요청 경로 · Batch 38

## 범위

이번 글은 “장애 보고서 91을 요약해 내부 #ops 채널로 보내 달라”는 요청 한 건을 끝까지 추적합니다.

1. 입력 rail이 원문을 검사하고 요청을 허용합니다.
2. 모델 응답의 JSON 구조는 통과하지만 본문에 비밀값이 남습니다.
3. 출력 rail이 비밀값을 제거하고 `MODIFY` 상태를 남깁니다.
4. 도구 rail이 전송 대상·권한·본문을 실행 직전에 다시 검사합니다.
5. 검사된 메시지 한 건을 전송하고 `messageId=184` 영수증으로 효과를 확인합니다.

## 학습 지도

직속 부모 지도는 에이전트 안전을 네 단계로 나눕니다.

`범위 → 검사 → 위협 → 격리`

이 글은 `검사`를 맡습니다. 입력 허용이 응답과 실행까지 승인하지 않으며, 새 상태가 생긴 위치에서 각각 다시 검사해야 한다는 사실을 부모 지도에 반환합니다.

## 공식 근거

- NVIDIA NeMo Guardrails v0.24.1 공식 문서에서 input·retrieval·dialog·execution·output rail의 실행 시점과 책임을 확인했습니다.
- JSON Schema 공식 설명에서 구조 검사가 field와 type 같은 선언된 제약을 확인하지만 도메인 의미와 실행 권한을 대신하지 않는 경계를 확인했습니다.
- 출처가 없던 `1ms 대 200ms`, `200배` 예시는 제거했습니다. 규칙과 모델 검사의 지연·비용·오류율은 대상 환경에서 측정해야 합니다.

## 작성 원칙

- 첫 설명보다 먼저 요청·입력 검사·응답 검사·실행 검사·영수증을 시각화합니다.
- `schema PASS`와 `안전한 내용`, `입력 ALLOW`와 `도구 실행 허용`을 같은 상태로 합치지 않습니다.
- 장면은 명시적인 재생과 이동에만 반응합니다.
- JavaScript가 꺼져도 다섯 장면과 결론을 같은 순서로 읽을 수 있습니다.
- 공통 조작부의 `sticky` 배치가 설명을 22px 덮던 문제를 제거하고 실제 좌표에서 겹침 0px을 확인했습니다.
