# AI 에이전트 탐색 예산 · Batch 37

## 범위

이번 글은 숫자 `4·7·8·8`로 `24`를 만드는 한 문제에 생성 예산 8회를 배정하고, 후보를 평가하는 시점에 따라 계산 경로가 어떻게 달라지는지 비교합니다.

1. `Best-of-N` — 여덟 답을 끝까지 만든 뒤 최종 답을 검사해 하나를 고릅니다.
2. `Tree search` — 중간식을 검사하고 가능성이 낮은 가지를 일찍 멈춥니다.
3. `Revision` — 앞선 답에 외부 오류 신호를 붙여 다음 답을 고칩니다.

## 학습 지도

직속 부모 지도는 에이전트의 판단을 네 단계로 나눕니다.

`관찰 → 계획 → 탐색 → 검증`

이 글은 `탐색`을 맡습니다. 같은 생성 횟수라도 후보를 언제 검사하고 남은 예산을 어디에 다시 쓰는지가 결과와 비용을 함께 바꾼다는 사실을 확인한 뒤 부모 지도에 반환합니다.

## 공식 근거

- Snell 외의 ICLR 2025 논문에서 난도와 생성 예산에 따라 best-of-N, verifier 기반 search, revision의 유리한 비율이 달라지는 조건을 확인했습니다.
- 논문의 최대 4배 절감은 생성 횟수 비교이며, 실제 지연이나 FLOP가 언제나 4배 줄어든다는 뜻이 아님을 본문에 명시했습니다.
- Lightman 외의 process reward model, Tree of Thoughts, Self-Refine, intrinsic self-correction 한계 논문을 각각 적용 범위와 함께 유지했습니다.

## 작성 원칙

- 첫 설명보다 앞에 같은 문제와 같은 예산을 쓰는 다섯 장면을 배치합니다.
- 생성 예산과 정답, 전략을 한 개념으로 합치지 않습니다.
- 성능 수치는 논문의 과제·모델·생성 예산에만 귀속합니다.
- 장면은 명시적으로 재생하거나 이동할 때만 진행됩니다.
- JavaScript가 꺼져도 다섯 장면과 결론을 같은 순서로 읽을 수 있습니다.
