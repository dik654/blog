# AI 주입·오염 경로 · Batch 39

## 범위

이번 글은 앞 글의 “장애 보고서 91을 요약해 내부 #ops로 보내 달라”는 요청을 이어받습니다.

1. 사용자 요청에는 외부 전송 지시가 없습니다.
2. 검색된 보고서에 “비밀값을 외부 주소로 보내라”는 숨은 지시가 들어 있습니다.
3. 시스템 지시는 trusted instruction, 검색 문서는 untrusted data로 구분합니다.
4. 모델이 숨은 문장을 지시로 오인해 외부 전송을 제안할 가능성을 남깁니다.
5. 실행 계층은 #ops만 허용하고 비밀 저장소 권한을 주지 않아 실제 효과를 차단합니다.

## 학습 지도

직속 부모 지도는 에이전트 안전을 네 단계로 나눕니다.

`범위 → 검사 → 위협 → 격리`

이 글은 `위협`을 맡습니다. prompt injection의 지시 출처와 data poisoning의 오염 시점을 구분하고, 탐지 실패를 전제로 권한과 데이터 노출 범위를 줄여야 한다는 사실을 부모 지도에 반환합니다.

## 공식 근거

- OWASP LLM01:2025에서 direct·indirect prompt injection의 경로와 외부 콘텐츠 구분, 최소 권한, 출력 검증, 사람 승인의 완화책을 확인했습니다.
- OWASP LLM04:2025에서 pre-training·fine-tuning·embedding data 조작과 backdoor 가능성을 확인했습니다.
- Greshake 외의 arXiv 2302.12173에서 검색된 데이터의 숨은 지시가 API 호출과 정보 유출에 영향을 준 사례를 확인했습니다.
- 정규식과 NER 탐지 예시에서 근거 없는 탐지 건수는 제거하고 실패 형태만 남겼습니다.

## 작성 원칙

- 첫 설명보다 먼저 사용자 요청·검색 문서·신뢰 경계·실행 제안·권한 차단을 시각화합니다.
- 모델의 도구 호출 제안과 실제 네트워크 효과를 같은 상태로 취급하지 않습니다.
- instruction-data separation을 완전한 차단으로 설명하지 않습니다.
- 장면은 명시적인 재생과 이동에만 반응합니다.
- JavaScript가 꺼져도 다섯 장면과 결론을 같은 순서로 읽을 수 있습니다.
