## 원 대화 핵심

### 4계층 배치 원칙 (신규 글의 척추)
| 성격 | 배치 | 예 |
|---|---|---|
| 항상 지켜야 하는 규칙 | AGENT.md / system policy | 운영 DB 수정 금지, 비밀정보 출력 금지 |
| 특정 상황의 절차 | Playbook | DB 장애 대응, 롤백, 보안 사고 |
| 재사용 가능한 실행 능력 | Skill | 로그 검색, k8s 상태 확인, 스키마 읽기 |
| 과거 기록·지식 | Wiki | 장애 원인, 설계 결정, 프로젝트 역사 |

- AGENT.md 전부 넣기: 누락 없음 vs 토큰 비용·중요 규칙 묻힘.
- Skill = lazy loading: 초기 context엔 이름/사용 조건/위치만, 상세는 선택 시 로드 → 지침용 검색 인덱스 역할. 스킬 100개 시나리오로 토큰 효율 설명.
- **Skill 호출 실패가 핵심 리스크**: 존재함 ≠ 발견함 ≠ 호출함 ≠ 올바르게 적용함. 따라서 **중요한 규칙은 Skill에만 두면 안 됨** — 이게 4계층 배치의 근거.

### Playbook vs Skill
- Playbook = 특정 문제의 절차·정책("DB 장애 때 무엇을"), Skill = 재사용 능력("DB 상태를 조회하는 법"). Playbook이 여러 Skill을 순서대로 사용.
- Playbook의 체감 장점: 사람·AI가 동일 절차 공유, 절차 단위 수정, 사고 대응 재사용, 이의 제기 용이.

### Subagent vs Skill
- Skill = 지침(실행 주체는 현재 에이전트), Subagent = 별도 실행 주체(독립 context, 결과 반환). Skill은 방법, Subagent는 그 방법을 수행하는 작업자.
- **하청 문제**: Main → Sub → Sub-sub로 넘길수록 목적 손실·제약 누락·책임 불명·요약 과정 정보 손실. 사용자와 직접 대화하는 에이전트가 최종 책임.

## 글의 각도

훅: **"중요한 규칙을 어디에 두는가는 신뢰성 설계다"** — skill 호출 실패 확률이 배치 원칙을 강제한다는 논리 전개. Claude Code 실물(CLAUDE.md/skills/subagents)로 4계층을 실증하면 Claw Code 트랙 차별점과 연결.
개인 경험 일반화 가능: 서브에이전트 의도 드리프트(미명세 경계를 상대 prior로 메움 → 제약 명시·출력 계약·독립 검증) — 내부 프로젝트 언급 없이 패턴만.

## 채우기 전 확인
