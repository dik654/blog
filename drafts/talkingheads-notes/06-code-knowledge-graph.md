# 06 · 코드 지식그래프 (Graphify)와 graph explosion

- **상태**: 신규 글 후보
- **위치**: codebase-analysis 카테고리 (현재 글이 얇아 확장 여지 큼). 대안: ai/articlesAgentOps.ts.

## 원 대화 핵심

- Graphify = 코드·문서(소스, Markdown, PDF, 다이어그램)를 분석해 엔티티·관계를 지식 그래프로 구성하는 도구. 목적: 에이전트가 매번 전체 저장소를 탐색하는 대신 구조화된 관계를 조회 (예: API → Handler → Service → Repository → DB Table).
- 장점: 의존성 탐색, 영향 범위 분석("이 함수 수정하면 어디가 영향?"), 코드-문서 연결, AI 답변 검증.
- **실사용 후기(한계)**: 그래프 조회가 무거움, 모노레포에서 파일 수 증가 시 성능 저하, 노드·관계 폭증, 갱신 비용, UI 과중 — 도구가 나쁘다기보다 대규모 모노레포·세밀한 요구에 안 맞음.
- **Graph Explosion**: import·호출·상속·API·DB·설정·문서·테스트·배포까지 전부 그래프에 넣으면 edge 폭증 → 실용 구조는 분리:
  - 핵심 관계 → Graph DB
  - 정확한 문자열 → Full-Text Search
  - 의미 검색 → Vector Search
- **자체 경량 도구 사례**: 필요한 관계만 추출 → 경량 인덱스 → CLI → 자체 UI. 장점: 속도·통제·맞춤화 / 단점: 직접 유지보수·언어별 파서·범용성 하락.
- **환각 검증 용도**: AI 주장 → 실제 코드 인덱스 조회 → 파일·함수·의존성 확인. LLM에게 자기 답변 재검토시키는 것보다 정적 분석 결과 대조가 확실 — CLI+UI를 붙인 진짜 이유.

## 글의 각도

훅은 **"전부 그래프에 넣으면 안 되는 이유"** — GraphRAG 유행 대비 하이브리드 저장(그래프/FTS/벡터) 분리 원칙. 실사용 후기 기반이라 벤더 글과 차별화.
둘째 훅: 그래프의 최고 용도는 탐색이 아니라 **환각 검증**(grounding)이라는 반전.
개인 경험 연결: OKF 방향에서 GraphRAG를 스킵한 판단과 같은 결론 — 단, 블로그에는 OJS/cola 내부 얘기 제외 원칙 유지, 일반론으로만.

## 채우기 전 확인
